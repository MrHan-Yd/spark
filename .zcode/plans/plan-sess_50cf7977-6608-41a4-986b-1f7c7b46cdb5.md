# 插件模块 WebView 缺陷修复计划

## 范围
仅修第三方 WebView 插件开发者会踩的几处缺陷。Native 运行时、zip 打包、marketplace 等不在本次范围。所有未实现能力统一走"明确 UNAVAILABLE"而非误导性错误。

## 修复项

### 1. `api_version` 校验（manifest.rs）
**问题**：清单 `api_version` 读了不校验，spec 第 11 节明确"不兼容版本不加载"。

**改法**：
- 在 `crates/plugin-manager/src/manifest.rs` 新增常量 `pub const SUPPORTED_PLUGIN_API_VERSION: u32 = 2;`，注释说明这是**插件清单规范版本**，区别于 `spark_ipc::protocol::API_VERSION`（IPC 线协议，=1）。
- 在 `validate()` 开头加：`if self.api_version > SUPPORTED_PLUGIN_API_VERSION { return Err(Manifest("api_version {} 不受支持（host 支持 <= {}）")) }`。
- 兼容策略：`api_version <= 当前` 均加载（向后兼容，preload 只增不删）；仅拒绝比 host 更新的规范版本。hello(=2)、echo(=1) 均通过，无回归。
- 补一个测试：构造 `api_version: 99` 的清单，断言 `validate()` 失败。

### 2. 关键词冲突检测（plugin-manager/src/lib.rs）
**问题**：两个插件用同一关键词时后者静默失效，开发者无任何提示。

**改法**：
- 新增 `pub fn keyword_conflicts(&self) -> Vec<KeywordConflict>`，遍历已加载的 webview 插件的 page keyword feature，按关键词分组找出被多于一个插件占用的项，返回 `{ keyword, plugin_ids: Vec<String> }`。
- 在 `scan_dir_with_source` 末尾调用一次，对每个冲突 `warn!(keyword=..., plugins=..., "关键字冲突：仅首个生效")`。保持首匹配胜出不变（确定性优先），只把冲突暴露出来。
- 补测试：装两个同关键词插件，断言 `keyword_conflicts()` 返回该项。

### 3. `clipboard.read_image` 误导性错误（host/src/app.rs）
**问题**：preload 声明了 `readImage`（spec 第 8.3 节承诺 base64 PNG），但 host `plugin_api_clipboard` 没有 `read_image` 臂，落到 `INVALID_ARGS: clipboard method read_image`——开发者误以为是参数错。

**改法**：
- 在 `plugin_api_clipboard` 的 fallback 前加显式臂：`"read_image" => bail!("UNAVAILABLE: clipboard.read_image 尚未实现")`，保留 `INVALID_ARGS` fallback 给真正的未知方法。
- preload 不动（已正确转发）。
- 同步更新 spec 第 8.3 节：给 `readImage` 标注"未实现"状态标记。
- **不做**真实图片编码实现：无 `image`/`base64` 依赖，离线下加依赖有风险，且 DIB 各变体（BITFIELDS/V4/V5/压缩）的正确性无法在此环境充分验证，违背质量门禁。真实 base64 PNG/BMP 实现作为后续独立任务。

### 4. `net`/`fs`/`shell` preload API 补全（plugin.preload.js）
**问题**：spec 第 8.3 节承诺 `spark.net.fetch`/`spark.shell.openExternal`/`spark.fs.read|write`，但 preload 根本没这些对象，开发者照 spec 写会得到 `TypeError: Cannot read properties of undefined`（像是 SDK 坏了）。host 端已正确返回 `UNAVAILABLE`。

**改法**：在 `plugin.preload.js` 的 `spark` 对象里补三个对象，全部走 `guarded`（客户端先按权限拦截，授权后再转 host 拿到 UNAVAILABLE）：
- `net: { fetch: (url, init) => guarded('net','net','fetch')({ url: String(url), init: init||null }) }`
- `shell: { openExternal: t => guarded('shell.open','shell','open_external')({ target: String(t) }) }`
- `fs: { read: p => guarded('fs.read','fs','read')({ path: String(p) }), write: (p,t) => guarded('fs.write','fs','write')({ path: String(p), text: String(t) }) }`
- host 无需改（fallback 已返回 `UNAVAILABLE: capability net/fs/shell`）。
- 同步更新 spec 第 8.3 节给这三组标注"未实现"。

### 5. 规范文档对齐（插件开发规范.md）
- 第 8.3 节 API 列表：给 `readImage`、`net.fetch`、`shell.openExternal`、`fs.read`、`fs.write` 加统一"⚠ 未实现（调用返回 UNAVAILABLE）"标记。
- 第 11 节版本与兼容：补一句校验规则"host 拒绝 `api_version > 当前支持版本`，向后兼容低版本"。
- 第 15 节脚注（line 523）已是"随后增量"，确认措辞一致即可。

## 不改动
- C# `PluginWindow.xaml.cs` / `HostIpcClient`：net/fs/shell/read_image 均走默认转发臂，无需改。
- host `clipboard.rs`：不加图片读取（见修复 3 说明）。
- `find_keyword_match` 路由逻辑：保持首匹配胜出，只加冲突告警。
- Native 插件运行时、zip 打包、`placeholder` 接 UI、`api_version` 之外的 manifest 校验。
