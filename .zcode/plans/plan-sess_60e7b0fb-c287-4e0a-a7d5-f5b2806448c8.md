# 实现 `spark.net.fetch`（host 代理网络请求）

## 目标与契约

按规范 §8.3 实现 `spark.net.fetch(url, init?)`，走 Rust host 代理（不暴露裸 fetch）：

- **请求**：`url: string`；`init?: { method?: string, headers?: Record<string,string>, body?: string }`
- **响应**：host 回 `{ status, headers, bodyText }`，preload 包装成规范形状 `{ status, headers, text(): Promise<string>, json(): Promise<any> }`
- **错误码**（沿用既有前缀约定，`ClassifyError` 零改动识别）：`PERMISSION_DENIED:` / `NETWORK_FAILED:` / `INVALID_ARGS:` / `UNAVAILABLE:`

## 方案选型（已确认离线可行）

**WinHTTP（windows crate feature），零新增依赖**：
- `crates/host/Cargo.toml:30` features 增加 `Win32_Networking_WinHttp`（**大小写必须精确如此**，写 WinHTTP 会解析失败且离线无法补救）。
- 已验证：本机缓存 `windows-0.61.3` 的 `Win32\Networking\WinHttp` 模块函数齐全（WinHttpOpen/Connect/OpenRequest/SendRequest/ReceiveResponse/ReadData/QueryHeaders/SetTimeouts 等全套），feature 只改编译开关，**Cargo.lock 零变动**。
- 否决项：ureq/reqwest（需联网拉新 crate，且 reqwest 拖 tokio）、手写 TcpStream（仅明文 HTTP）、UI 侧 C# HttpClient（违反"host 代理"架构与规范 §12）。

## 改动清单

### Rust host（核心）

1. **新模块 `crates/host/src/net_fetch.rs`**：
   - `NetRequest { url, method, headers: Vec<(String,String)>, body: Option<String> }` / `NetResponse { status: u16, headers, body: String }` / `execute(&NetRequest) -> Result<NetResponse>`
   - 参数校验（全部纯函数，可离线单测）：scheme 仅 http/https（否则 `INVALID_ARGS:`）；method 归一大写并限白名单 GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS；带 body 时 method 不得为 GET/HEAD；headers 过滤 `Host`/`Content-Length`（WinHTTP 自管）；请求体上限 1MB。
   - WinHTTP 同步调用：UA `Spark-PluginNet/1.0`；每请求独立 session（`WINHTTP_ACCESS_TYPE_DEFAULT` 走系统代理，测试路径用 `NO_PROXY` 参数隔离）；**总体 deadline 25s**（每次阻塞调用前按剩余预算设置 WinHttpSetTimeouts，保证不超过 UI 30s 预算）；响应体上限 10MB；body 按 UTF-8 lossy 解码（v1 文本语义，二进制另行规划）；重定向走 WinHTTP 默认策略（禁 https→http 降级）。
   - 测试：**本地 `TcpListener` 回环测试服务器**（127.0.0.1，无需外网）驱动真实 WinHTTP 路径，覆盖 200/404/带请求头/POST body/慢响应超时/超限响应；校验逻辑单测覆盖全部 INVALID_ARGS 分支。

2. **`crates/host/src/app.rs`**：
   - `plugin_api()`(:388) match 增加 `"net"` 分支：鉴权仿 clipboard `has("net")` → 拒绝 `bail!("PERMISSION_DENIED: net")`；锁内只做鉴权+args 解析为 `NetRequest`，返回新变体。
   - `PluginApiOutcome`(:93) 增加 `Net(NetRequest)` 变体（host 内部类型，不上线，不破坏 UI 兼容）。

3. **`crates/host/src/ipc_server.rs`**(:544-556)：锁外段处理 `PluginApiOutcome::Net` → `net_fetch::execute()`（仿 NativePage 先例：阻塞 IO 绝不持 `host.lock()`，否则 30s 冻结全部 IPC 含主窗查询）；失败错误信息原样回传（前缀即错误码）。

4. **`crates/ipc/src/protocol.rs:307`**：capability 注释补 `net`（无 schema 变更）。

### C# UI（小改）

5. **`ui/Spark.UI/Services/HostIpcClient.cs:530`**：超时选择 `capability == "rpc" ? 20 : 8` 改 switch 加 `"net" => 30`。
6. **`ui/Spark.UI/Assets/plugin.preload.js:145-149`**：桩改真实现——仿 clipboard(:107-109) **去掉 guarded 本地快拦**改为直连 `call('net','fetch',…)`（host 为权威鉴权，中途授权即时生效；host 拒绝时 `ShowPermissionDenied` 通用逻辑 + 已就绪的 `PermissionDisplayName` "net→访问网络"(:363) 自动弹提示条，零 UI 额外改动）；响应包装成 `{status, headers, text(), json()}`，`json()` 解析失败以 `INVALID_ARGS` reject。

### 文档

7. `插件开发规范.md` L292 实现状态行、L532-534 IPC 表；`WebView插件开发.md` L244-248 状态表：net 从"未实现"改为已实现（text()/json() 形状、10MB/25s 限制、UTF-8 文本语义写明）。

## 兼容性

- 旧 host + 新 UI / 新 host + 旧 UI：均走 `UNAVAILABLE: capability net` 优雅降级，无握手问题（capability 是字符串分支，`PluginApiParams` 零 schema 变更）。
