## 1. 一句话

**Spark 插件 = 一个能被 Spark 打开的窗口/页面，页面内容（功能）由开发者自己实现，Spark 只提供接入规范（清单 + 触发 + `spark.*` API）。**

- 插件不画主搜索窗；主窗由 Spark 统一渲染。
- 插件页面跑在 Spark 开出的**独立 WebView2 窗口**里，崩溃/卡死不影响主程序。
- 开发者只需写 `plugin.json` + `index.html`（+ 可选 JS/CSS/资源），打包成 `.spark-plugin` 即可安装。
- 需要原生能力（OCR、截图、重 IO、任意语言）的**重型插件**走 `runtime: native`（独立 exe），见 §10。

---

## 2. 设计原则

1. **低门槛**：前端开发者用 HTML/JS 即可开发，无需学 Rust/C#。
2. **规范稳定**：插件只依赖本规范（清单 + preload API），不依赖 Spark 内部结构。
3. **权限最小化**：能力按 `permissions` 白名单解锁，未声明的能力调用直接抛错。
4. **崩溃隔离**：插件窗口独立于主进程，插件页崩溃不拖垮 Spark。
5. **不打扰**：未被触发的插件不占资源、不弹窗、不预加载。

---

## 3. 插件包结构

最小可安装的插件包目录结构：

```
my-plugin/
  plugin.json          # 清单（必须）
  index.html           # 页面入口（webview 类型必须）
  icon.png             # 图标，建议 128×128（可选但强烈建议）
  README.md            # 给用户看的说明（可选）
  assets/              # 任意静态资源：js/css/图片/字体（可选）
  preload.js           # 自定义预加载脚本（可选，§8.4）
```

打包发布时，将整个目录压成 zip，扩展名改为 `.spark-plugin`。

安装后落盘位置：

| 类型 | 位置 |
|------|------|
| 正式安装 | `<Spark 安装目录>/plugins/<id>/`（内置插件与用户插件统一此目录） |
| 插件状态（启用/授权） | `<data_dir>/plugins-state.json`（应用管理，非用户手编） |
| 插件私有数据 | `<data_dir>/plugin-data/<id>/`（仅插件可读写） |
| 开发模式 | 开发者自选本地目录（不拷贝，改文件即热重载） |

> `<data_dir>` 为 `%APPDATA%/Spark`，或 host 同目录存在 `data/` 时的便携模式 `<安装目录>/data`。
> 插件目录默认 `<安装目录>/plugins`，用户可在设置-插件页改为任意路径并迁移现有插件。
> **更新/重装保留**：Inno 升级只替换它自己装的内置插件文件，用户装的插件子目录不在安装清单内、原样保留；卸载也不删用户插件（安装器不对 `plugins/` 加 `[UninstallDelete]`）。
> **一期安装方式**：从本地目录导入（选含 `plugin.json` 的文件夹）。`.spark-plugin` zip 解压安装待 `zip` 依赖就绪后补充。

## 4. 清单 `plugin.json`

清单是插件的唯一入口描述，JSON 格式，UTF-8 无 BOM。

### 4.1 字段总表

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 反向域名风格，全局唯一，如 `com.spark.translate`；必须含 `.` |
| `name` | string | 是 | 显示名，建议 ≤ 8 字符 |
| `version` | string | 是 | 语义化版本，如 `0.1.0` |
| `api_version` | number | 是 | 本规范版本，当前 `2` |
| `runtime` | string | 是 | `webview`（页面插件）或 `native`（exe 插件，§10） |
| `main` | string | 是 | webview: `index.html`；native: exe 文件名 |
| `icon` | string | 否 | 图标文件相对路径，建议 png 128×128 |
| `author` | string | 否 | 作者名 |
| `description` | string | 否 | 一句话描述 |
| `homepage` | string | 否 | 插件主页/仓库 URL |
| `permissions` | string[] | 否 | 需要的能力白名单，见 §7 |
| `features` | object[] | 是 | 触发方式列表，见 §5；至少 1 个 |
| `preload` | string | 否 | 自定义预加载脚本路径（§8.4） |
| `window` | object | 否 | 默认窗口尺寸/行为，见 §4.3 |

### 4.2 完整示例

```json
{
  "id": "com.spark.translate",
  "name": "翻译",
  "version": "0.1.0",
  "api_version": 2,
  "runtime": "webview",
  "main": "index.html",
  "icon": "icon.png",
  "author": "Spark 示例",
  "description": "输入 tr 触发翻译",
  "homepage": "https://github.com/...",
  "permissions": ["clipboard", "net", "notify"],
  "features": [
    {
      "type": "keyword",
      "keyword": "tr",
      "title": "翻译",
      "subtitle": "输入 tr 翻译后面的内容",
      "mode": "page"
    }
  ],
  "window": {
    "width": 480,
    "height": 360,
    "resizable": true,
    "alwaysOnTop": false
  }
}
```

### 4.3 `window` 字段

| 子字段 | 类型 | 默认 | 说明 |
|--------|------|------|------|
| `width` | number | 480 | 初始宽度（逻辑像素） |
| `height` | number | 360 | 初始高度 |
| `minWidth` | number | 240 | 最小宽度 |
| `minHeight` | number | 180 | 最小高度 |
| `resizable` | bool | true | 是否可调整大小 |
| `alwaysOnTop` | bool | false | 是否默认置顶 |
| `frame` | bool | true | 是否显示系统标题栏；`false` 时由插件自绘标题栏 |

## 5. 触发方式 `features`

`features` 数组定义用户如何进入插件。每个 feature 描述一个触发入口。

### 5.1 `type: keyword`（关键字触发，一期主推）

用户在主输入框输入 `<keyword> <参数>`，主列表出现一条该插件的命令项，回车即打开插件窗口。

```json
{
  "type": "keyword",
  "keyword": "tr",
  "title": "翻译",
  "subtitle": "输入 tr 翻译后面的内容",
  "mode": "page",
  "placeholder": "输入要翻译的文本…"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | string | 是 | 触发关键字，不含任何空白字符（含全角空格）；支持中文；建议 1-4 字符；全局唯一，冲突时先装先生效并提示 |
| `title` | string | 是 | 列表项标题 |
| `subtitle` | string | 否 | 列表项副标题 |
| `mode` | string | 是 | `page`（开窗）；`list` 已移除（见 §5.4） |
| `placeholder` | string | 否 | 进入插件后输入框的占位提示（可选） |

进入插件后，`spark.input.text` = 去掉 `tr ` 前缀后的内容。

### 5.2 `type: regex`（正则匹配，二期）

主输入框内容匹配某正则时，主列表追加该插件入口。适用于"输入 IP 自动出现 IP 查询插件"这类场景。

```json
{
  "type": "regex",
  "pattern": "^\\d{1,3}(\\.\\d{1,3}){3}$",
  "title": "IP 查询",
  "subtitle": "查询 IP 归属地",
  "mode": "page"
}
```

### 5.3 `type: root`（无前缀挂载，二期）

插件挂在根输入框上，每次输入都参与匹配（常配合 `spark.onInput` 实时响应）。谨慎使用，影响主搜索性能，一期不开放。

### 5.4 `mode` 语义

| `mode` | 行为 | 适用 `runtime` |
|--------|------|----------------|
| `page` | 选中命令回车 → Spark 打开 WebView2 插件窗口 | `webview`、`native` |
| `list` | **已移除**：旧 native 的"exe 直接向搜索框应答、返回结果项"模式不再存在（native 清单声明 `commands`/`list` 即被拒绝；webview 的 `list` feature 不参与路由） | — |

`webview` 插件只支持 `mode: page`；`native` 插件的 `features` 同样仅允许 `mode: page`（旧 `commands`/`keywords` 字段校验直接拒绝）。

> **路由契约（实现侧）**：host 在 `host.query` 中对 enabled 的插件（webview 与 native 同构）做 page 模式关键字匹配，命中时在结果最前插入一条 `Candidate`：`source=plugin`、`plugin_id=<id>`、`target="plugin:page:<id>"`、默认 action 的 `target` 同值。UI 见 `target` 以 `plugin:page:` 开头即调 `host.plugin.open` 打开插件窗口，不走 `host.invoke`。native 候选打开的是同一套页面窗口，exe 不参与搜索过程（只随页面懒启动）。

## 6. 窗口生命周期

```
用户输入关键字 → 主列表出现插件命令项
        │ 回车
        ▼
Spark 打开 WebView2 插件窗口，加载 index.html
        │ 注入 spark.* preload（按权限解锁）
        ▼
插件页就绪，读取 spark.input.*，开始工作
        │
        ├─ 用户关闭窗口 / spark.window.close()
        ▼
Spark 销毁 WebView2 实例，回收资源；插件私有数据保留
```

- 插件窗口关闭后，其 `plugin-data/<id>/` 数据不删除，下次打开仍在。
- 同一插件可配置是否允许多开（默认单开：再次触发时聚焦已存在窗口）。

## 7. 权限 `permissions`

插件在清单中声明所需能力，**首次启用/首次打开时由用户授权**。未声明的能力，对应 `spark.*` 调用抛 `PermissionDenied` 错误。

| 权限 | 解锁的 API | 风险 | 说明 |
|------|------------|------|------|
| `clipboard` | `spark.clipboard.*` | 中 | 读写系统剪贴板 |
| `notify` | `spark.notify.*` | 低 | 系统通知 |
| `net` | `spark.net.*` | 中 | 网络请求，走 host 代理转发，不暴露裸 `fetch` |
| `shell.open` | `spark.shell.openExternal` | 中 | 用系统默认程序打开 URL/文件 |
| `fs.read` | `spark.fs.read` | 高 | 读插件沙箱外的文件（需用户在授权时指定范围） |
| `fs.write` | `spark.fs.write` | 高 | 写文件 |
| `window.alwaysOnTop` | `spark.window.setAlwaysOnTop` | 低 | 窗口置顶 |
| `db` | `spark.db.*` | 无 | 插件私有键值存储（默认开放，无需声明） |

`spark.db.*` 和 `spark.window.*`（除置顶外）默认开放，不需要声明。

高危权限（`fs.read`/`fs.write`/`shell.execute`-类）首次调用时二次弹窗确认，用户可逐项拒绝。

## 8. 接入 API（`spark.*`）

`spark` 是 Spark 在插件窗口加载时注入的全局对象。所有能力按 `permissions` 白名单解锁。所有返回 Promise 的方法均为异步。

### 8.1 输入上下文 `spark.input`

```js
spark.input.text       // string，去掉触发前缀后的用户输入
spark.input.command    // string，触发的关键字，如 "tr"
spark.input.rawQuery   // string，主输入框原始完整内容
```

只读属性，进入插件时填充。

### 8.2 窗口控制 `spark.window`

```js
await spark.window.setTitle(title: string)
await spark.window.resize(width: number, height: number)
await spark.window.center()
await spark.window.close()
await spark.window.setAlwaysOnTop(enabled: boolean)   // 需 window.alwaysOnTop
```

### 8.3 系统能力

```js
// 剪贴板（需 clipboard）
const text = await spark.clipboard.readText()
await spark.clipboard.writeText(text)
const b64 = await spark.clipboard.readImage()   // ⚠ 未实现：返回 UNAVAILABLE（规划 base64 PNG）

// 通知（需 notify）
await spark.notify.show({ title: string, body?: string })

// 网络（需 net）—— 走 host 代理，受 host 网络策略约束
const resp = await spark.net.fetch(url: string, init?: {
  method?: string,
  headers?: Record<string, string>,
  body?: string
})
// resp: { status, headers, text() -> Promise<string>, json() -> Promise<any> }

// Shell（需 shell.open）
await spark.shell.openExternal(urlOrPath: string)   // 系统默认程序打开

// 文件（需 fs.read / fs.write，高危，授权时定范围）
const text = await spark.fs.read(path: string)
await spark.fs.write(path: string, text: string)
```

> **实现状态**：`clipboard.readImage`、`spark.net.*`、`spark.shell.*`、`spark.fs.*` 当前**未实现**，调用统一返回 `UNAVAILABLE`（preload 已提供 API 桩，避免开发者拿到 `TypeError`）。已可用：`clipboard.readText/writeText`、`notify.show`、`db.*`。

> **不开放给 webview 插件**：任意命令执行（`shell.execute`）、全局键盘钩子、截图、访问其他插件数据。这些能力留给 `runtime: native` 重型插件（§10）。

### 8.4 私有存储 `spark.db`

每个插件有独立的键值存储沙箱，落盘于 `plugin-data/<id>/db`，无需声明权限。

```js
await spark.db.set(key: string, value: any)     // value 可序列化为 JSON
const value = await spark.db.get(key: string)    // 不存在返回 null
await spark.db.remove(key: string)
const keys = await spark.db.keys()               // string[]
await spark.db.clear()
```

### 8.5 事件 `spark.on`

```js
spark.onEnter(cb: () => void)      // 进入插件窗口后触发（DOM 就绪后）
spark.onInput(cb: (text: string) => void)   // 主输入框文本变化（用于挂载模式，二期）
spark.onResize(cb: (w: number, h: number) => void)
spark.onClose(cb: () => void)      // 窗口即将关闭前触发，可做存盘
```

### 8.6 错误处理

未授权能力调用抛标准 `Error`，`error.code` 为：

| code | 含义 |
|------|------|
| `PERMISSION_DENIED` | 未声明或用户拒绝该权限 |
| `PERMISSION_SCOPE` | 超出授权范围（如 fs 路径不在授权目录） |
| `NETWORK_FAILED` | 网络请求失败 |
| `INVALID_ARGS` | 参数不合法 |
| `UNAVAILABLE` | 该能力在当前平台/版本不可用 |

```js
try {
  await spark.clipboard.writeText("x")
} catch (e) {
  if (e.code === "PERMISSION_DENIED") { /* 引导用户去设置授权 */ }
}
```

### 8.7 自定义预加载 `preload.js`

若清单声明 `preload` 字段，Spark 会在页面 DOM 就绪前、`spark` 注入后额外执行该脚本。用于注入自定义全局工具、polyfill、或封装 `spark.*` 成更友好的 SDK。

```js
// preload.js 示例：把 spark.net.fetch 封装成类 axios
window.myApi = {
  async get(url) {
    const r = await spark.net.fetch(url)
    if (r.status !== 200) throw new Error(`HTTP ${r.status}`)
    return r.json()
  }
}
```

## 9. 开发与调试

### 9.1 开发模式

设置 → 插件 → 开发者区 → **加载开发目录**，选择本地插件目录。Spark 不拷贝文件，源文件改动后按 `Ctrl+R` 或窗口菜单"重载"热刷新。

### 9.2 控制台

插件窗口支持 WebView2 开发者工具（开发模式下自动启用，正式安装版默认关闭）。右键 → 检查，或 `spark` 开发模式 API `spark.dev.openDevTools()`。

### 9.3 最小可运行插件

```
hello/
  plugin.json
  index.html
```

`plugin.json`：
```json
{
  "id": "com.spark.hello",
  "name": "Hello",
  "version": "0.1.0",
  "api_version": 2,
  "runtime": "webview",
  "main": "index.html",
  "permissions": [],
  "features": [
    { "type": "keyword", "keyword": "hi", "title": "Hello", "mode": "page" }
  ]
}
```

`index.html`：
```html
<!doctype html>
<html><head><meta charset="utf-8"><title>Hello</title></head>
<body style="font-family:system-ui;padding:24px">
  <h3>你好，Spark</h3>
  <div id="out"></div>
  <script>
    document.getElementById('out').textContent =
      '你输入的是：' + spark.input.text
  </script>
</body></html>
```

加载开发目录 → 主输入框输入 `hi Spark` → 回车 → 弹窗显示"你输入的是：Spark"。

### 9.4 打包

开发完成后，将插件目录压成 zip，改扩展名为 `.spark-plugin`：

```
translate.spark-plugin  (zip)
  ├─ plugin.json
  ├─ index.html
  ├─ icon.png
  └─ assets/
```

> 注意：zip 根目录应直接是插件文件，不要外面再套一层目录。

## 10. 重型插件（`runtime: native`）

供需要原生 OS 能力（OCR、截图选区、大量 IO、特定语言生态）的高级开发者使用。**纯应用模型**已实现（2026-09-04 改版；旧 `commands`/list 搜索融合模式已移除）。

- 插件 = 含 `plugin.json + exe + page.html` 的目录，`runtime: "native"`，`main` 指向 exe，`page` 指向页面（必填，相对 `.html` 路径）。
- **纯应用模型**：native 插件**不允许**声明旧 `commands`/`keywords` 字段（exe 直接向搜索框应答的 list 模式，声明即校验失败、拒绝加载）；`features` 允许且仅限 `mode: "page"`——关键字在搜索框产出候选（含真前缀建议），打开的正是插件页面窗口，exe 不参与搜索过程。页面入口 = 搜索框关键字候选 或 插件卡片「打开」/「调试」。
- 页面 = 全部 UI：Spark 用与 webview 同款的插件窗口（WebView2）代开，页面 JS 可用 `spark.*` 能力 + `spark.rpc(method, args)`（host 转发 `plugin.page` RPC 调用 exe 的原生逻辑，返回插件自定义 JSON；不设权限，同源同信任）。
- 与 host 通过 stdin/stdout 的 length-prefixed JSON-RPC 通信（4 字节小端长度前缀 + UTF-8 JSON body；帧编解码见 `crates/ipc/src/frame.rs`；host 发送的方法：`plugin.initialize/page/shutdown`；`query`/`invoke`/`cancel` 协议保留但不再发送）。
- exe 生命周期与页面绑定：懒启动（页面首次 RPC 才 spawn + 握手），**关闭页面即优雅关停进程**；崩溃/超时自动重建。host 校验响应 id 与请求 id 一致，故插件 stdout 必须纯净协议帧。
- Rust 开发者引用 `spark-sdk` crate，main 调 `spark_sdk::run_loop(&mut plugin)` 即可（帧编解码 + initialize/page/shutdown 分发内置，`Plugin::page` 宿主原生逻辑）。
- 远期：`commands[].mode:"page"` 自建顶层原生窗口（需 `window.create` 权限；纯应用模型不满足的场景，如截图选区浮层）。
- 详见 `crates/sdk`、`plugins/echo`（纯页面示例，端到端可跑）与 [Native插件开发.md](./Native插件开发.md)。

普通用户/前端开发者无需关心本节。

## 11. 版本与兼容

- 清单 `api_version` 标记本规范版本。当前 `2`（webview 插件引入）。
- Spark host 在加载清单时校验 `api_version`；不兼容版本不加载并在设置页提示。
- 校验规则：host 拒绝 `api_version > 当前支持版本`（当前 `2`）的清单；`api_version <= 当前` 均加载（向后兼容，preload API 只增不删）。
- preload API 只增不删；能力收紧走权限化，不直接移除签名。
- 升级插件版本号遵循语义化版本；`api_version` 跨大版本时 Spark 保留旧实现并标记兼容期。

## 12. 安全约束（开发者必读）

1. 插件页面运行在独立 WebView2，与主进程隔离；但 `spark.*` 是受信任通道，不要在插件页内 eval 不可信内容。
2. `net` 请求走 host 代理，host 可记录/限流；不要试图绕过。
3. `fs` 高危权限授权时限定目录范围，插件不得越界。
4. 不得在插件中收集用户隐私上传未声明用途的服务器；`net` 权限仅用于插件功能本身。
5. 官方插件由官方私钥签名（Ed25519，详见 [插件签名规范.md](./插件签名规范.md)），host 安装时验签，签名破损一律拒装；本地开发免签名；三方开发者自助签名待后续子阶段。

## 13. 路线图

| 阶段 | 内容 |
|------|------|
| **一期** | `runtime: webview` + `keyword` 触发 + `page` 模式 + 核心 `spark.*` API + 本地安装/开发模式 + 设置页三块 |

## 14. 清单 Schema 速查（供校验器实现）

```jsonc
{
  "id": "string, reverse-domain, required",
  "name": "string, required",
  "version": "semver string, required",
  "api_version": "number, required (current: 2)",
  "runtime": "'webview' | 'native', required",
  "main": "string, required",
  "icon": "string, optional",
  "author": "string, optional",
  "description": "string, optional",
  "homepage": "string, optional",
  "permissions": "string[], optional",
  "preload": "string, optional",
  "features": [
    {
      "type": "'keyword' | 'regex' | 'root'",
      "keyword": "string, when type=keyword",
      "pattern": "string, when type=regex",
      "title": "string, required",
      "subtitle": "string, optional",
      "mode": "'page' | 'list', required",
      "placeholder": "string, optional"
    }
  ],
  "window": {
    "width": "number, default 480",
    "height": "number, default 360",
    "minWidth": "number, default 240",
    "minHeight": "number, default 180",
    "resizable": "bool, default true",
    "alwaysOnTop": "bool, default false",
    "frame": "bool, default true"
  }
}
```

> **不加 `official` / `signed` 字段**："是否官方"由 host 对包内 `signature.json` 的验签结果判定（见 [插件签名规范.md](./插件签名规范.md) §1），而非清单自报字段——自报字段可被任意伪造。`PluginInfo.sign_state`（`official`/`third_party`/`unsigned`/`invalid`）由 host 随 `host.plugin.list` 返回，UI 只展示。

## 15. IPC 方法参考（host.plugin.*，一期实现）

UI ↔ Host 间 JSON-RPC 方法名（开发者一般无需关心；仅供 host/UI 实现与调试对照）：

| 方法 | 方向 | 参数 | 返回 | 说明 |
|------|------|------|------|------|
| `host.plugin.list` | UI→Host | — | `PluginInfo[]` | 已装插件清单（含 enabled/granted/source/features/**sign_state**） |
| `host.plugin.install` | UI→Host | `{path, force?, require_signature?}` | `PluginInstallOutcome` | 从本地目录导入安装。**内部含签名校验步骤**（不新增方法）：拷贝前对源目录全量验签，`invalid` 一律拒装，`unsigned`+`require_signature=true` 拒装，验过记 `official`/`third_party`/`unsigned` |
| `host.plugin.uninstall` | UI→Host | `{id}` | `{ok}` | 卸载标准来源插件 |
| `host.plugin.toggle` | UI→Host | `{id,enabled}` | `{ok}` | 启用/禁用 |
| `host.plugin.grant` | UI→Host | `{id,permissions[]}` | `{ok}` | 授权权限 |
| `host.plugin.devload` | UI→Host | `{dir}` | `{id}` | 加载开发目录（不拷贝） |
| `host.plugin.open` | UI→Host | `{id,input,command}` | `PluginOpenInfo` | 取开窗所需信息（main 绝对路径/window/permissions/preload；native 纯应用返回 page 绝对路径） |
| `host.plugin.set_dir` | UI→Host | `{path,migrate}` | `{ok}` | 更换插件目录并可选迁移 |
| `host.plugin.page_closed` | UI→Host 通知（无 id，无响应） | `{id}` | — | 插件页面窗口关闭通知（fire-and-forget，host 不回包）：native 纯应用插件的 exe 随之优雅关停（webview 无操作） |
| `host.plugin.api` | UI→Host | `{plugin_id,capability,method,args}` | `{ok,data}` | `spark.*` 特权能力桥（clipboard/notify/db/rpc） |

一期 `host.plugin.api` 支持的 capability：`db`（set/get/remove/keys/clear，默认开放）、`clipboard`（read_text/write_text，需授权；read_image 未实现，返回 UNAVAILABLE）、`notify`（show，需授权）、`rpc`（仅 native 插件：页面 `spark.rpc` 经 host 转发 `plugin.page` 调用插件 exe，不设权限；webview 插件调用返回 UNAVAILABLE）。`net`/`fs`/`shell` 的 preload API 桩已就位，host 端返回 UNAVAILABLE，随后增量实现。

### 15.1 仓库源配置（二期）

自定义仓库 URL 列表通过**已有的** `host.get_config` / `host.set_config` 管理，不新增 IPC 方法。

`HostConfig` 新增字段 `plugin_registry_urls: Vec<String>`（自定义仓库 `registry.json` 完整 URL 列表，空数组 = 仅用官方，支持多个）。`SetConfigParams` 同名新增，空值语义：`None` = 不修改，`Some(vec)` = 替换整个列表，`Some(vec![])` = 清除全部。

仓库目录抓取和插件下载安装由 UI 直接完成（HttpClient + ZipArchive），安装时复用 `host.plugin.install`。详见 [插件市场与仓库.md](./插件市场与仓库.md)。
