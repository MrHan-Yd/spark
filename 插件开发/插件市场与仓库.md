# Spark 插件市场与仓库规范

> 状态：**二期规范定稿**（2026-08-21）
> 适用版本：`registry.schema: 1`
> 相关：[插件开发规范.md](./插件开发规范.md) · [WebView插件开发.md](./WebView插件开发.md) · [Native插件开发.md](./Native插件开发.md)
>
> 本文件是**插件仓库（registry）的契约**。仓库主人照本文件搭建仓库，Spark host/UI 照本文件抓取和安装。第三方搭建自己的仓库也以本文件为准。

---

## 1. 一句话

**插件仓库 = 一个 HTTP 可访问的目录，根目录放 `registry.json` 索引，子目录按「插件名/版本号/插件文件」组织。Spark 抓索引 → 用户选插件 → Spark 下载仓库 zip → 解压对应版本子目录 → 安装。**

- 仓库可以托管在 GitHub（推荐）或任意 HTTP 服务器上。
- Spark 内置一个官方仓库地址，用户可在设置中配置自己的仓库地址。
- 浏览市场时用户选择「官方仓库」或「自定义仓库」。
- 安装走 host 已有的 `host.plugin.install`（从本地目录安装），市场只负责下载 + 解压 + 交接。

---

## 2. 仓库目录结构

```
spark-plugins/                         ← 仓库名（官方默认 spark-plugins）
  registry.json                        ← 中央索引（必须，根目录）
  translate/                           ← 文件夹名 = 插件英文名
    plugin.json                        ← 元信息（人看 + 参考，非安装用）
    0.1.0/                             ← 版本文件夹 = 可安装的完整插件内容
      plugin.json                      ← 真正的清单（host 安装时读这个）
      index.html                       ← webview 插件页面
      assets/                          ← 任意资源
    0.2.0/
      plugin.json
      index.html
      assets/
  echo/
    plugin.json
    0.1.0/
      plugin.json                      ← native 插件清单
      spark-plugin-echo.exe            ← native 插件 exe
```

### 规则

| 规则 | 说明 |
|------|------|
| 文件夹名 = 插件英文名 | 仓库存放目录名，与 `plugin.json` 的 `id` 不要求一致（`id` 是反向域名）；仅用于人类浏览 |
| 版本文件夹 = 语义化版本号 | 如 `0.1.0`、`0.2.0`，与 `plugin.json` 的 `version` 字段一致 |
| 版本文件夹内容 = 完整可安装插件 | 即 `.spark-plugin` 解压后的目录结构：`plugin.json` + `index.html`/`exe` + 资源 |
| `registry.json` 是唯一索引 | host/UI 只读这一个文件获取全量目录，不枚举目录、不调 GitHub API |
| 每个插件根目录的 `plugin.json` | 仅供参考/浏览，host 安装时读的是**版本文件夹内**的 `plugin.json` |

> 仓库主人新增/更新插件时，需要同步更新 `registry.json`。

## 3. registry.json 规范

UTF-8 无 BOM 的 JSON。`schema` 字段标记格式版本，当前 `1`。

### 3.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `schema` | number | 是 | 格式版本，当前 `1` |
| `name` | string | 是 | 仓显示名，如 `"Spark 官方插件仓库"` |
| `zipball_url` | string \| null | 条件 | 仓库完整 zip 下载地址，用于 `version.url` 为 null 时的子目录提取安装。若所有版本的 `url` 均非 null（纯预打包仓库），可为 null |
| `updated` | string | 否 | ISO 8601 时间戳，仓库最后更新时间 |
| `plugins` | array | 是 | 插件条目列表，见 §3.2 |

### 3.2 插件条目 `plugins[]`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 反向域名插件 ID，如 `com.spark.translate`；全局唯一 |
| `name` | string | 是 | 显示名 |
| `description` | string | 否 | 一句话描述 |
| `author` | string | 否 | 作者 |
| `homepage` | string | 否 | 插件主页/仓库 URL |
| `icon` | string \| null | 否 | 图标 URL（绝对地址），建议 128×128 png |
| `runtime` | string | 是 | `"webview"` 或 `"native"` |
| `permissions` | string[] | 否 | 该插件声明的权限白名单（与版本内 `plugin.json` 的 `permissions` 一致），供 UI 安装前展示。缺失时 UI 显示「安装时确认」 |
| `latest` | string | 是 | 最新版本号，如 `"0.1.0"` |
| `versions` | array | 是 | 版本列表，见 §3.3 |

### 3.3 版本条目 `versions[]`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 语义化版本号，如 `"0.1.0"` |
| `path` | string \| null | 条件 | 仓库内子目录路径，如 `"translate/0.1.0"`；`url` 为 null 时必填，`url` 有值时可为 null |
| `url` | string \| null | 否 | 直接下载地址（预打包 zip）；有值时优先使用，跳过 zipball |
| `sha256` | string \| null | 否 | 下载文件 SHA-256 校验值；有值则安装时校验，不匹配拒绝 |
| `size` | number \| null | 否 | 下载文件字节数，用于 UI 进度显示 |
| `released` | string | 否 | 发布日期，ISO 8601 |

### 3.4 完整示例

## 4. 仓库源（source）

Spark 支持一个官方仓库源 + 多个自定义仓库源，用户在设置 → 插件 → 插件市场中切换：

| 源 | 配置方式 | 说明 |
|----|----------|------|
| 官方仓库 | 代码内常量 `OFFICIAL_REGISTRY_URL` | 完整 registry.json URL，如 `https://raw.githubusercontent.com/<owner>/spark-plugins/main/registry.json`；始终可选，用户不可改 |
| 自定义仓库（0~N 个） | 设置页增删 URL 列表，存入 `HostConfig.plugin_registry_urls: Vec<String>` | 每条是一个完整 registry.json URL（任意 HTTP 地址）。未配置则不展示自定义选项；配置了多个就有多个可选 |

> **URL 语义**：配置值是 `registry.json` 文件的**完整绝对 URL**，UI 直接用 `HttpClient.GetAsync(url)` 抓取，不拼接任何后缀。

### 4.1 源切换 UI

浏览市场时顶部有源选择器（ComboBox 下拉）：

- 始终有「官方仓库」选项
- 自定义仓库列表为空时不显示自定义选项（下拉里只有官方仓库）
- 配置了 N 个自定义仓库时，下拉中追加 N 条「自定义: \<url 简称\>」选项
- 选中某源后加载该仓库的 registry.json，展示插件列表

自定义仓库配置区（在源选择器下方）：

- 一个可编辑的 URL 列表：每行一个 TextBox + 删除按钮，底部一个「添加仓库」按钮
- 「保存」按钮将完整列表写入 `HostConfig`（通过 `host.set_config`）
- 列表为空 = 无自定义仓库（下拉只有官方仓库）
- 保存后刷新源选择器下拉项

### 4.2 官方 URL 常量

```csharp
// Services/RegistryService.cs
public const string OfficialRegistryUrl =
    "https://raw.githubusercontent.com/OWNER/spark-plugins/main/registry.json";
```

> `OWNER` 为仓库主人的 GitHub 用户名。仓库创建后替换。代码中用常量，不暴露给用户修改。

### 4.3 自定义仓库规范要求

自定义仓库与官方仓库**使用完全相同的 `registry.json` 格式**（§3）和安装流程（§5）。搭建自定义仓库必须满足以下要求：

| 要求 | 说明 |
|------|------|
| `registry.json` 可达 | 配置的 URL 用 HTTP GET 能取到 UTF-8 JSON，`schema == 1` |
| 每个版本可下载 | 每个版本的 `url` 或 `path` + 仓库 `zipball_url` 至少有一个可用 |
| 非托管平台服务器 | 服务器未提供仓库级 zip 归档时，每个版本必须填 `url` 指向可独立下载的 zip；若服务器自带 zip 归档能力，可用 `path` + `zipball_url` |
| zip 结构（`url` 方式） | zip 根目录直接是插件文件（`plugin.json` + `index.html` + 资源），不套外层目录 |
| zip 结构（`zipball` 方式） | 同 GitHub zipball：顶层一个目录前缀，`path` 子目录下是插件文件 |
| `sha256` 校验 | 推荐为每个版本填 `sha256`，防止下载损坏 |
| HTTPS | 强烈建议 HTTPS；HTTP 时 UI 显示安全提示 |

> **zipball 说明**：GitHub 等托管平台自带仓库归档 zip 下载能力。若自定义仓库所在服务器未提供仓库级 zip 归档，则每个版本必须填 `url` 指向可独立下载的 zip。

**非 GitHub 自定义仓库示例**（纯 HTTP 服务器）：

```
# 服务器目录结构
/var/www/my-spark-plugins/
  registry.json                          ← 索引
  translate/
    translate-0.1.0.zip                   ← 预打包 zip（根目录直接是插件文件）
    translate-0.2.0.zip
```

```json
{
  "schema": 1,
  "name": "我的插件仓库",
  "zipball_url": null,
  "updated": "2026-08-21T10:00:00Z",
  "plugins": [
    {
      "id": "com.spark.translate",
      "name": "翻译",
      "runtime": "webview",
      "latest": "0.2.0",
      "permissions": ["clipboard", "net"],
      "versions": [
        {
          "version": "0.2.0",
          "path": null,
          "url": "https://my-server.com/my-spark-plugins/translate/translate-0.2.0.zip",
          "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
          "released": "2026-08-21"
        }
      ]
    }
  ]
}
```

> **安全提示**：自定义仓库是用户主动信任的第三方源，Spark 不验证其真实性（代码签名在三期实现）。UI 在切换到自定义仓库时显示提示「你正在连接第三方仓库，插件安全性由仓库主人负责」。多个自定义仓库互不影响，各自独立抓取和安装。

## 5. 安装流程

```
用户打开插件市场 → 选源（官方/自定义）
        │
        ▼
UI 用 HttpClient GET 直接抓取 registry_url（即配置的完整 registry.json URL）
        │ 解析为 RegistryIndex，校验 schema == 1
        ▼
展示插件列表（名称/描述/作者/最新版本/已装版本）
        │ 用户点「安装」或「更新」
        ▼
判断 version.url：
  ├─ 有值 → 下载该 URL（预打包 zip）→ 解压全部内容到 temp 目录
  └─ null → 下载 registry.zipball_url → 解压 zip → 只提取 version.path 子目录到 temp
        │
        ▼
（可选）校验 sha256：version.sha256 有值则比对，不匹配拒绝安装
        │
        ▼
调用 host.plugin.install { path: "<temp_dir>" }
        │ host 复制到 plugins_dir，版本比较，状态管理
        ▼
安装完成 → UI 刷新插件列表 → 清理 temp 目录
```

### 5.1 zipball 子目录提取

GitHub zipball 下载后顶层目录名含 commit hash 前缀：

```
owner-spark-plugins-abc123/          ← 顶层（不确定的 hash 后缀）
  registry.json
  translate/
    0.2.0/
      plugin.json
      index.html
```

提取逻辑（C# `ZipArchive`）：

1. 打开 zip，遍历**所有** entry，收集每个 entry `FullName` 中第一个 `/` 之前的部分作为候选顶层目录名，去重后得到唯一顶层目录集合。
2. 若顶层目录不唯一（多个根）→ 视为格式错误，中止安装并报错。
3. 令 `prefix` = 唯一顶层目录名（如 `owner-spark-plugins-abc123`）。
4. 目标前缀 = `{prefix}/{version.path}/`（如 `owner-spark-plugins-abc123/translate/0.2.0/`）。
5. 遍历所有 entry，只保留 `FullName.StartsWith(targetPrefix)` 的。
6. 若目标前缀下**无任何 entry** → 版本路径不存在，中止并报错「仓库中未找到该插件版本」。
7. 验证目标前缀下存在 `plugin.json`（清单必须存在），否则报错。
8. 剥掉前缀，写入 temp 目录（路径校验见 §9）。

> **预打包 zip（`version.url` 有值）**：直接解压全部内容到 temp 目录，无前缀剥离，同样执行 §9 路径校验和配额限制。

### 5.2 已装版本检测

UI 调 `host.plugin.list` 获取已装插件列表，与 registry 条目交叉比对：

- registry 中有、本地无 → 显示「安装」按钮
- registry 中有、本地有、版本相同 → 显示「已安装」（灰色）
- registry 中有、本地有、registry 版本更高 → 显示「更新」按钮
- registry 中有、本地有、registry 版本更低 → 显示「已安装（v本地 更新）」

版本比较复用 host 侧 `cmp_version` 逻辑（UI 侧做字符串语义化比较即可，格式简单）。

### 5.3 安装结果

复用已有的 `PluginInstallOutcome`：

| action | 含义 |
|--------|------|
| `installed` | 全新安装 |
| `updated` | 覆盖更新（registry 版本 ≥ 本地） |
| `confirm_downgrade` | registry 版本 < 本地，需用户确认降级 |

UI 侧处理同本地安装：`confirm_downgrade` 时弹确认框，用户同意后带 `force: true` 重新安装。

## 6. 发布流程（仓库主人）

### 6.1 新增插件

1. 在仓库根目录创建插件英文名文件夹（如 `translate/`）。
2. 在其中创建版本文件夹（如 `0.1.0/`），放入完整插件内容（`plugin.json` + `index.html` + 资源，或 native 的 exe）。
3. 在插件根目录放一份 `plugin.json`（元信息，供浏览参考）。
4. 更新 `registry.json`：在 `plugins` 数组中添加该插件条目。
5. 提交推送。

### 6.2 更新插件版本

1. 在插件文件夹下新建版本文件夹（如 `0.2.0/`），放入新版本完整内容。
2. 更新 `registry.json`：该插件条目的 `versions` 数组头部加新版本，`latest` 指向新版本。
3. 提交推送。

### 6.3 GitHub zipball 地址

`zipball_url` 用 GitHub 的 archive 接口：

```
https://github.com/<owner>/<repo>/archive/refs/heads/<branch>.zip
```

默认分支 `main`。如用其他分支，`registry.json` 和 `zipball_url` 要一致。

### 6.4 预打包 zip（可选）

如果不想下载整个仓库 zip（仓库大时），可以为每个版本提供预打包 zip：

1. 将版本文件夹内容压成 zip（根目录直接是插件文件，不要套一层）。
2. 上传到 GitHub Release asset 或仓库内。
3. 在 `registry.json` 的 `version.url` 填该 zip 的下载地址。

`url` 有值时 host 跳过 zipball，直接下载该 zip。适合大仓库或 native 插件（exe 体积大）。

## 7. 配置与 IPC

### 7.1 设计原则

仓库目录抓取（`registry.json`）和插件下载安装由 **UI 直接完成**（HttpClient + ZipArchive），不经 host IPC。安装时复用已有的 `host.plugin.install`。host 无需引入 HTTP/zip 依赖。

自定义仓库 URL 通过**已有的** `host.get_config` / `host.set_config` 管理，不新增 IPC 方法。

### 7.2 HostConfig 字段变更

`HostConfig`（`crates/host/src/config.rs`）新增：

```rust
pub plugin_registry_urls: Vec<String>,  // 自定义仓库 registry.json 完整 URL 列表，空 = 仅用官方
```

- `host.get_config` 返回值自动包含此字段（HostConfig 整体序列化）。
- `host.set_config` 的 `SetConfigParams` 新增同名字段 `plugin_registry_urls: Option<Vec<String>>`。
- **空值语义**（与现有 SetConfigParams 一致）：
  - `None`（JSON 中字段缺省）→ 不修改，保持原列表
  - `Some(vec!["url1", "url2"])` → 替换整个列表为这些 URL
  - `Some(vec![])`（空数组）→ 清除所有自定义仓库，恢复仅用官方
- handler 中合并逻辑：`if let Some(urls) = params.plugin_registry_urls { config.plugin_registry_urls = urls; }`

### 7.3 UI 侧读取

- 官方仓库 URL：C# 常量 `RegistryService.OfficialRegistryUrl`，不来自 config。
- 自定义仓库 URL 列表：`host.get_config` → `HostConfigDto.PluginRegistryUrls`（`List<string>`，空列表 = 未配置）。
- UI 根据用户选源决定用哪个 URL 抓取 `registry.json`。源选择器下拉项 = 官方 + 每个自定义 URL。

### 8.1 市场面板位置

设置 → 插件 → 顶部工具栏增加「插件市场」按钮，或插件设置页内增加「市场」子面板（与「已安装」并列切换）。

│      └─ 自定义: my-server.com/plugins        │

## 9. 安全约束

### 9.1 Zip Slip 路径穿越防护

zipball 和预打包 zip 解压时统一执行以下校验：

1. **规范化路径校验**：对每个 entry 的目标路径 `Path.GetFullPath(Path.Combine(tempDir, relativePath))` 做规范化，验证结果**以 `tempDir` 为前缀**（`GetFullPath(tempDir)` + 目录分隔符）。不在 tempDir 内的 entry 一律拒绝。
2. **绝对路径拒绝**：entry 的 `FullName` 若以 `/`、`\` 或盘符（`C:`）开头，拒绝。
3. **反斜杠统一**：zip entry 路径统一用 `/` 分隔，但恶意 zip 可能用 `\`，校验前先 `Replace('\\', '/')`。
4. **`..` 拒绝**：规范化后的路径含 `..` 段或越出 tempDir 的，拒绝。
5. **符号链接跳过**：跳过 zip 中的符号链接 entry（`ExternalAttributes` 标记为 symlink），不提取。
6. **重复条目**：同一目标路径被多个 entry 映射时，后者覆盖前者（与 `ExtractToFile(overwrite: true)` 一致），但日志记录。

### 9.2 解压配额（防 zip bomb）

| 限制项 | 上限 | 超限行为 |
|--------|------|----------|
| 下载文件大小 | 50 MiB | 中止下载，报错 |
| 解压后总大小 | 100 MiB | 中止解压，清理 temp，报错 |
| 解压文件数量 | 10,000 个 | 中止解压，清理 temp，报错 |
| 单文件解压大小 | 50 MiB | 中止解压，清理 temp，报错 |

> 任何一项配额超限均**立即停止解压、清理 temp 目录、安装失败**。不存在「跳过超限文件后继续」的语义——部分解压的插件不完整，不能安装。

### 9.3 下载安全

1. **超时**：下载 30 秒超时，弱网友好提示。
2. **大小上限**：下载前检查 `Content-Length` 响应头，超 50 MiB 不开始下载；下载中累计字节超限也中止。
3. **重定向限制**：`HttpClientHandler.AllowAutoRedirect = true`，最多跟随 5 次重定向（.NET 默认）。
4. **SSRF 防护**：官方仓库 URL 是代码常量，不可被用户篡改；自定义仓库 URL 由用户主动输入，视为用户信任，不做内网地址拦截（用户自担风险）。
5. **HTTPS 优先**：官方仓库强制 HTTPS；自定义仓库若用 HTTP，UI 显示安全提示「该仓库使用未加密连接」。

### 9.4 校验

1. **SHA-256 校验**：`version.sha256` 有值时，下载后计算文件 SHA-256 比对，不匹配拒绝安装并报错。
2. **sha256 格式校验**：`sha256` 字段非 null 有值时，必须是 64 位十六进制字符串。格式非法视为索引错误，拒绝该版本安装并报错「sha256 格式非法」，不跳过校验。`sha256: null` 表示不校验，正常放行。

### 9.5 输入校验与错误处理

| 场景 | 处理方式 |
|------|----------|
| 仓库不可达 / 网络超时 | UI 显示「无法连接仓库，请检查网络或仓库地址」 |
| `registry.json` JSON 解析失败 | UI 显示「仓库索引格式错误」，不崩 |
| `schema` 字段缺失或 `> 1` | UI 显示「仓库格式版本不受支持，请更新 Spark」 |
| `schema == 1` 但字段缺失 | 跳过不完整的插件条目，日志记录，正常展示其余 |
| `zipball_url` 为 null 但某版本 `url` 也为 null | 该版本不可安装，UI 显示「该版本无可用下载地址」 |
| 版本路径在 zipball 中不存在 | 报错「仓库中未找到该插件版本」 |
| `plugin.json` 在版本目录中缺失 | 报错「插件清单缺失」 |
| `latest` 与 `versions` 列表不一致（latest 不在 versions 中） | 以 `versions` 列表为准，`latest` 字段忽略并日志记录 |
| 版本号非标准 semver | 跳过该版本条目，日志记录 |
| sha256 格式非法（非 64 位 hex） | 拒绝该版本安装，报错「sha256 格式非法」 |
| sha256 校验不匹配 | 拒绝安装，报错「文件校验失败，可能已损坏」 |

### 9.6 其他

1. **temp 目录清理**：安装完成或失败后均清理 temp 目录（`try/catch/finally` 保证），不残留。
2. **不自动安装**：用户必须手动点击安装/更新，不做后台静默安装。
3. **三期签名校验**：市场上架强制代码签名在三期规划中（见 §13.5）。当前二期依赖仓库准入控制（人工审核）+ 运行时权限白名单 + 用户侧透明度，见 §13 安全治理。
4. **原子临时目录**：每次安装用唯一临时目录名（GUID），避免并发安装冲突。

## 10. 版本与兼容

- `registry.schema` 标记 registry.json 格式版本。当前 `1`。
- host/UI 解析时校验 `schema`；`schema > 当前支持版本` 时拒绝并提示「仓库格式版本过高，请更新 Spark」。
- `schema <= 当前` 均加载（向后兼容，字段只增不删）。
- 新增可选字段不 bump schema；移除字段或改语义才 bump。

## 12. 快速上手（仓库主人）

### 12.1 创建仓库

1. GitHub 创建仓库 `spark-plugins`（public）。
2. 创建 `registry.json`（照 §3.4 示例改）。
3. 每个插件创建 `插件名/版本号/` 目录，放入完整插件内容。
4. 推送到 `main` 分支。

### 12.2 验证

1. 浏览器打开 `https://raw.githubusercontent.com/<owner>/spark-plugins/main/registry.json`，确认 JSON 可访问。
2. 下载 `https://github.com/<owner>/spark-plugins/archive/refs/heads/main.zip`，确认 zip 可下载。
3. 解压 zip，确认 `插件名/版本号/` 目录结构正确，内含 `plugin.json`。

### 12.3 接入 Spark

1. 替换代码中 `OFFICIAL_REGISTRY_URL` 的 `<owner>`（如果是官方仓库主人）。
2. 或在 Spark 设置 → 插件 → 市场 → 自定义仓库地址填入 `registry.json` 的 raw URL。

## 13. 安全治理与防投毒

### 13.1 仓库治理模型

| 仓库类型 | 治理方式 | 信任基础 |
|----------|----------|----------|
| 官方仓库 | **人工审核的 Git 仓库**。只有仓库主人（及受信任协作者）有合并权。每个插件 PR 必须经过 review 才能合入。不是开放投稿市场。 | 仓库主人的审核 |
| 自定义仓库 | 用户主动配置，自担风险。Spark 不验证其真实性。 | 用户对第三方的信任 |

> **关键防线**：二期没有代码签名，防投毒的核心是**仓库准入控制**——官方仓库主人审核每个插件后才合入 `registry.json`。开放投稿 + 自动上架的市场模式在三期签名校验落地后才考虑。

### 13.2 运行时隔离

| 插件类型 | 隔离能力 | 风险等级 |
|----------|----------|----------|
| webview | WebView2 沙箱 + 权限白名单（clipboard/notify/net/fs）。不能直接调 OS API。`spark.*` 是唯一特权通道，未声明权限的调用直接拒绝。**残余风险**：若声明了 `net`/`fs` 权限，仍可外传数据或读写文件，需审核（§13.4）。 | 中低 |
| native | 独立 exe，**拥有完整 OS 能力**。权限模型二期粗粒度。可以做任何事（文件、网络、进程、注册表）。 | **高** |

> native 插件是最大的攻击面。审核时必须格外谨慎（见 §13.4）。UI 安装 native 插件时显示额外警告「原生插件拥有完整系统权限，请确认来源可信」。

### 13.3 用户侧透明度

1. **安装前展示权限**：市场列表中每条插件显示声明的 `permissions`，用户点击安装前能看到要授予哪些能力。
2. **native 插件警告**：runtime 为 native 的插件安装时弹额外提示。
3. **手动安装**：用户必须手动点击安装/更新，不做后台静默安装（§9.6 #2）。
4. **权限授权是显式的**：安装后插件首次使用某权限时，用户在设置中逐项授权（已有的一期机制）。
5. **自定义仓库切换提示**：切到自定义仓库时 UI 提示「你正在连接第三方仓库，插件安全性由仓库主人负责」。每个自定义仓库独立，互不影响。

### 13.4 官方仓库审核清单（仓库主人 / PR Reviewer 必读）

每个插件 PR 合入前，审核者必须检查：

**通用检查：**
- [ ] `plugin.json` 的 `id` 合规（反向域名，含 `.`），不与已有插件冲突
- [ ] `permissions` 最小化（只声明功能必需的权限，不申请多余能力）
- [ ] `fs.read`/`fs.write`/`shell.open` 等高危权限有合理理由
- [ ] `homepage` 指向可访问的源码仓库（可审查性）
- [ ] `author` 填写真实标识

**webview 插件额外检查：**
- [ ] 阅读 `index.html` 及引用的 JS/CSS 源码全文
- [ ] 无混淆代码（obfuscated/minified 但无源码提供 → 拒绝）
- [ ] 无外部动态脚本注入（`eval`、`new Function`、动态 `<script src>` 到非可信 CDN）
- [ ] 无数据外发：检查所有外联通道——`fetch`/`XMLHttpRequest`、`WebSocket`、`navigator.sendBeacon`、`<img src>` / `<script src>` / `<link href>` 指向外部、`<form action>` 外部提交、`window.open` 外部跳转
- [ ] 无尝试访问 `spark` 对象以外的不受信任通道
- [ ] 若声明了 `net` 权限，审查请求目标 URL 是否合理（是否外传用户数据）
- [ ] 若声明了 `fs` 权限，审查读写路径范围是否最小化

**native 插件额外检查（高风险）：**
- [ ] 必须有可审查的源码仓库（`homepage` 指向），不接受闭源 exe
- [ ] 阅读源码全文（不限语言：Rust、C/C++、Go、Python 等），检查进程启动（`Command`/`CreateProcess`/`exec`）、文件操作、网络调用、注册表/系统配置修改
- [ ] 审查依赖链：`Cargo.lock`/`go.mod`/`package.json` 等依赖是否来自可信源，无可疑第三方依赖
- [ ] **二进制与源码对应性**：要求开发者提供构建说明，审核者最好能自行复现编译并比对产物 hash；无法复现则拒绝
- [ ] exe 用 VirusTotal 或本地杀软扫描
- [ ] 实际行为测试：在沙箱/虚拟机中运行插件，监控文件/网络/进程行为，确认与声明的 `permissions` 和功能一致
- [ ] 检查 `commands` 中声明的触发关键字不与已有插件冲突

### 13.5 当前阶段 vs 三期安全能力

| 能力 | 二期（当前） | 三期 |
|------|-------------|------|
| 仓库准入控制 | ✅ 人工审核（官方仓库主人 review） | ✅ + 自动化扫描辅助 |
| 运行时沙箱 | ✅ webview 权限白名单 | ✅ + native 权限模型细化 |
| 用户权限透明 | ✅ 安装前展示 + 显式授权 | ✅ |
| 传输安全 | 官方仓库强制 HTTPS；自定义仓库建议 HTTPS（HTTP 时 UI 提示）；sha256 有值时校验完整性，无值不校验 | ✅ + 三期 sha256 强制 |
| 代码签名 | ❌ | ✅ 插件用开发者私钥签名，Spark 安装前验签 |
| 防仓库被入侵 | ❌ 仓库被入侵则可投毒（靠 Git 历史追溯） | ✅ 签名验证：即使仓库被入侵，伪造签名会被拒绝 |
| 远程禁用 | ❌ 无 kill switch | ✅ 可下发禁用列表 |

> **sha256 的局限**：`registry.json` 中的 sha256 能检测下载损坏和传输篡改，但**不能**防止仓库本身被入侵——攻击者可以同时替换插件文件和 `registry.json` 中的 sha256。代码签名（三期）才能解决这个问题，因为签名私钥不在仓库里。

### 13.6 事件响应

**发现恶意插件时（官方仓库）：**
1. 仓库主人立即从 `registry.json` 中移除该插件条目。
2. 删除对应版本目录。
3. 推送修复。用户下次刷新市场不再看到该插件。
4. 已安装该插件的用户：二期无远程禁用能力，需通过公告通知用户手动卸载。三期可下发禁用列表自动禁用。

**官方仓库被入侵时：**
1. 立即收回仓库写权限。
2. 审查 Git 历史，确认哪些插件被篡改。
3. 恢复未被篡改的版本。
4. 三期签名落地后：被篡改的插件因签名不匹配自动被 Spark 拒绝安装，用户不受影响。
